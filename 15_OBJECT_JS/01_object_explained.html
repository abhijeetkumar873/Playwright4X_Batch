JavaScript Objects: Why Does It Print "fail"?

This example shows that assigning an object to another variable does not make a separate object. Both variables can point to the same object.

The code

let a = { status: "pass" };
let b = a;
b.status = "fail";
console.log(a.status);

Picture it

Think of the object as one shared box. The variables a and b are two labels pointing to that same box.

Step by step

  1. let a = { status: "pass" } creates one object. Its status starts as "pass".
  2. let b = a makes b refer to the same object as a. It does not create a second object.
  3. b.status = "fail" changes the status property on that shared object.
  4. a.status reads the changed property, so the console prints fail.
Remember: a and b are different variable names, but they point to the same object. Changing the object through either name is visible through the other.
Console output: fail

Want a separate, shallow copy?

For this simple object, the spread syntax makes a new object. Updating the copy does not change the original object's top-level status.

const original = { status: "pass" };
const copy = { ...original };

copy.status = "fail";

console.log(original.status); // "pass"
console.log(copy.status);     // "fail"

This is a shallow copy: nested objects inside the original would still be shared unless copied separately.
